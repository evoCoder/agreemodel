# Интерфейсы ядра «Согласие»

Состояние на версию 0.3.0.dev0 (ветка feat/core). Описание для ТЗ (Р1.6, п. 4.4.2), веб-интерфейса и адаптера к
внешнему симулятору.

## 1. Входы борта (от смежных технологий)

| Вход | Источник | Поля | Темп в базовом сценарии |
|---|---|---|---|
| Оценка своего положения | автономная навигация (ФТ № 4) | x, y (м, система координат маршрута), σ (м) | 4 Гц (запись `uav`) |
| Обнаружения | бортовой датчик и детектор | время (мкс), x, y (м), дисперсия (м²), распределение по 5 классам | кадры 5 Гц |
| Время | синхронизация времени | общая шкала, мкс | — |
| Связь | радиомодем | широковещательная и адресная передача пакетов | — |

## 2. Записи хранилища (реплицируются между бортами)

У каждой записи один писатель — борт-источник. Глобальный ключ — (источник, ключ),
версия — порядковый номер источника.

| Ключ | Поля |
|---|---|
| `uav` | `x`, `y` — оценка положения борта; `st` — состояние |
| `trk/<n>` | `x`, `y`, `vx`, `vy` — оценка трека; `pxx`, `pxy`, `pyy` — ковариация (с ошибкой навигации борта); `t0`, `t1` — первое и последнее наблюдение, мкс; `n` — число отметок; `cls` — распределение классов; `st` — `A` активен, `L` потерян, `M` объединён с другим своим треком (`into`) |

## 3. Обмен между бортами

| Сообщение | Передача | Содержание |
|---|---|---|
| `DIGEST` | широковещательно, 5 Гц и при появлении соседа | вектор версий: источник → последняя версия |
| `REQ` | адресно | источник → (от версии, до версии) — недостающий диапазон |
| `DELTA` | широковещательно | часть диапазона одного источника (не больше одного пакета канала) |

Приём части после пропуска — часть откладывается, пропуск дозапрашивается у отправителя.

## 4. Выход — общая картина (для распределения задач, ФТ № 2)

Картина — детерминированная функция хранилища: одинаковое содержимое хранилищ даёт
побитово одинаковую картину (поле `digest`). Выгрузка — `picture.json`:

| Поле объекта | Смысл |
|---|---|
| `id` | идентификатор объекта, одинаковый на всех бортах (хеш ключа первого трека) |
| `x`, `y`, `cov` | положение и ковариация (ковариационное пересечение треков разных бортов) |
| `cls` | распределение классов |
| `sources` | треки-источники `борт/trk/n` |
| `unresolved` | неоднозначное сопоставление — противоречие не скрыто (Р1.3) |

Состав группы — список `uavs` (положение, время последнего сведения, признак работы).

## 5. Адаптер к внешнему симулятору

- Сценарий — TOML или JSON одной структуры (`scenario.json` выгрузки загружается обратно
  без изменений результата): `python -m agreemodel run scenario.json --out dir`.
- Выход: `summary.json` (показатели ФТ № 1), `series.csv` (временной ряд), `picture.json`
  (картина каждого борта), `scenario.json` (все исходные данные).
- Стратегия ассоциации подключается через `fusion.register_associator` и ключ
  `fusion.association`.
- Наблюдение за прогоном — `Simulation(sc, on_sample=f)`.
- Подача наблюдений и навигации из внешнего симулятора вместо встроенных моделей мира и
  датчика (входы раздела 1) — задача НИОКР (подэтап 1.1, проект адаптера).

## 6. Показатели (summary.json)

| Поле | Показатель |
|---|---|
| `quantum_s` | квант: от кадра датчика до картины, в которой кадр отражён |
| `restores[].store_conv_s` | восстановление согласованности: от восстановления связи (или появления присоединившегося борта) до получения всеми работающими бортами набора изменений, накопленного к этому моменту |
| `fix_latency_s` | задержка фиксации нового наблюдения: от кадра, подтвердившего новый трек, до записи в хранилище |
| `detect_to_fix_s` | от первого обнаружения объекта бортом до записи трека (включает подтверждение трека — зависит от датчика) |
| `settle_conv_s`, `final_pictures_identical` | сходимость картин после остановки записи |
| `records_missing_per_uav` | потери записей |
| `picture.duplicates`, `mixed_objects`, `false_objects` | качество сопоставления по эталону |
| `net.kbps_per_uav`, `net.air_busy_pct` | нагрузка на канал |
| `picture_compute_ms`, `store_kbytes_max` | затраты на пересчёт картины, объём хранилища борта |
